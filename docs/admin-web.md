# フレーズブレンダー管理画面

運営者用の統計閲覧・NG管理画面。HTTPSと管理者認証で保護します。統計DBへの接続はSELECT専用のままです。NG設定だけを共有ボリュームで更新します。

- URL: https://192.168.40.175:8084/
- ユーザー名: `admin`
- 初期パスワード: 自鯖の `/home/bamboo/phraseblender/.env.admin` に保存（権限600）。`ADMIN_PASSWORD`を参照します。Gitには保存しません。
- HTTPSは自鯖のIPに対する自己署名証明書です。初回は証明書の確認が必要です。有効期間は365日。外部公開時はドメインと正規証明書に置き換えてください。

## 配置・更新

既存 `/home/bamboo/phraseblender` に `admin_web/`、`access_control.py`、`ng_word_filter.py`、`config_store.py`、両Composeファイルを配置し、`python3 admin_web/deploy.py` を実行します。初回だけ、Botで有効なNGワード（ファイル・環境変数）を共有ボリュームへ移行し、以後はこの共有設定を正とします。既存設定を再デプロイで上書きしません。Botの再構築と管理画面の構築を行い、DBは再起動しません。共通Pythonファイルは配置時に `admin_web/runtime/` へコピーします。この生成フォルダーはGit対象外です。

NGワードの初期リスト `text/ng_words.txt` は既存運用の共有設定を上書きしません。NGユーザー・サーバーは `access-policy` ボリュームの `policy.json`、NGワードは同ボリュームの `ng_words.txt` が実設定です。ファイルロックと原子的置換で管理画面と緊急復旧ツールからの同時更新による消失を防ぎます。Botは次回操作から設定を再読込します。サーバー退出は通常60秒以内です。

管理画面だけのソース更新では、共通コードを最新の `admin_web/runtime/` にコピーしたうえで `docker compose -f docker-compose.admin.yml up -d --build admin-web` を実行します。停止は `docker compose -f docker-compose.admin.yml stop admin-web`。別ComposeのBot・DBを削除しないよう、`--remove-orphans`や`down -v`を使わないでください。

## NG登録・解除

1. ログイン後「NG・通報情報」の対象を選択します。
2. 「対象 → 操作 → 対象データ → 登録（解除）」の順で操作します。対象データは入力可能なプルダウンです。サーバー・ユーザーは「名前 / ID」から選択、または数字のDiscord IDを直接入力できます。登録候補はDBのサーバー履歴・ゲーム参加者、解除候補は現在のNG設定です。ワードは現在のNGワード・登録済みワード（最大1,000種類）から選択、または1～100文字で直接入力できます。ワードは改行・制御文字・空白のみ・#始まりを受け付けません。
3. 「NG登録」または「NG解除」を選び、「確認して実行」で対象を確認します。一覧の「解除」からも解除できます。
4. 更新成功後に一覧が再取得されます。同じ内容の再登録・再解除でも他の項目を消しません。

サーバーのNG登録ではBotが退出します。解除しても自動では再参加しないため再招待してください。運営サーバーとBot自身のユーザーIDはサーバー側でNG追加を禁止します。Web認証は共通管理者アカウントのため、操作する人のDiscord IDとの対応付けはありません。

更新APIは管理者認証・固定の同一Origin・CSRFトークン・JSON形式を確認します。NG設定だけを更新し、DBの更新権限は付与しません。`ADMIN_ORIGIN`はアクセスURLを変える場合に変更が必要です。共有設定のためUID/GIDはBotと同じ100:101です。Dockerイメージのユーザーを変更するときは両方を合わせてください。

Webの成功操作は共有ボリューム内の `web-audit.jsonl` に日時・共通管理者名・対象・操作・値を記録します。監査記録の書込みでエラーになった場合は設定が反映済みの可能性があるため、画面を再読込して確認してください。DiscordのNG管理コマンドは廃止し、NG登録・解除は管理画面から行います。ボット利用時の操作ログは従来どおり記録します。

## 表示の定義

NG設定は更新ボタンで実設定を再読込します。名前の記録がない対象はIDと「名称未取得」を表示します。ワードは正規化後の部分一致判定です。一般語に含まれる短いワードを登録すると誤検知し得ます。読込異常は0件へ置き換えずエラー表示にします。

通報は最新50件と総件数・通知未記録件数を表示します。「通知済み」はDiscordへの通知記録があるという意味で、対応完了ではありません。対応状況の列はないため未対応件数は算出しません。

登録数・ランキングは `delete_flg=FALSE`。参加者は `join_members.user_id` の全体ユニーク数。Bot導入先はDiscord APIから取得します。ゲーム稼働数は開始フラグがTRUEのサーバー数。登録者IDは既存の文字列形式のため、ユーザー名変更前後を完全統合できません。登録日時がないため日別登録数は算出しません。基本統計は60秒キャッシュします。

## 確認方法

1. 未認証でアクセスし401になることを確認。
2. 管理者でログインし、3種類の件数・ランキングが表示されることを確認。
3. DBの同一条件のCOUNTと画面の値を比較。
4. 狭い画面でもカードとランキングを閲覧できることを確認。
5. Discord取得失敗時には導入数を「—」と表示し、取得失敗の案内が出ることを確認。

## NGワードのCSV入出力

NGワード欄の「CSVダウンロード」で現在の全ワードを取得できます。UTF-8 BOM付き、1列、見出し `ng_word` です。Excelで数式として解釈され得る値は先頭にアポストロフィを付けます。再アップロード時にこの接頭辞を復元します。

「CSVアップロード」でファイルを選び「内容を確認して追加」を押します。検証結果として新規追加予定件数・登録済み件数・先頭20件を表示します。確認すると既存設定に追加し、正規化後の重複をまとめます。置換・一括削除は行いません。プレビューでは設定を書き換えず、本登録時にも全行を再検証します。

UTF-8（BOM有無）・Shift_JIS（CP932）、1MB未満、最大10,000データ行。1列・1行1ワード、1～100文字。先頭見出し `ng_word` / `word` / `NGワード` は省略可能です。空行は無視します。不正な列数・引用符・改行入りワード・制御文字・#始まり等がある場合は、全件を拒否して設定を変更しません。CSVの内容は1回のロック・原子的保存で追加します。元のファイル名は保存先に使用せず、アップロードデータもファイルとして保持しません。取り込み操作は監査ファイルへ記録します。

動作確認: 管理コンテナで `python -m unittest admin_web.test_app admin_web.test_ng_csv`。自鯖の配置ディレクトリで `python3 admin_web/verify_csv.py` を実行すると、既存のCSVをダウンロード・確認・再取り込みしてNG設定の一致を確認します。
