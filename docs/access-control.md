## 制限の内容

- NGサーバー：招待後にボットが自動退出します。起動時と60秒ごとの確認でも退出します。招待画面自体は拒否できません。
- NGユーザー：全サーバーで、参加、登録、更新、削除、ワード取得、設定、通報などのボット操作を拒否します。
- 以前に開いたボタン・モーダルや候補検索も制限します。登録者・通報内容やNG一覧は拒否メッセージに表示しません。
- NGユーザーは登録完了待ちの対象から除外します。すでに保存された参加記録・ワードは自動削除しません。
- NG解除後、サーバーには必要に応じて再招待します。NGユーザーは次の操作から再利用できます。

DiscordサーバーからユーザーをBAN・キックする機能ではありません。
また、公開チャンネルに過去に投稿したメッセージや画像の閲覧までは制限しません。

Discordの `/ng-user`、`/ng-server`、`/ng-list` は廃止しました。
ボット側のNG判定、操作拒否、自動退出、保存済みNG設定は維持します。

## 保存と反映

DB変更はありません。NG設定は専用Dockerボリューム `access-policy` 内の
`/app/access-policy/policy.json` に保存します。再起動・再ビルドで保持します。
`down -v` はNG設定もDBも削除するため実行しないでください。
初回作成時だけ、イメージ内の `config/access_policy.json` を初期値として使用します。
ユーザーの制限は次の操作から反映し、NGサーバーの退出は通常60秒以内です。
退出失敗は次の定期確認で再試行し、退出までの間も操作を拒否します。
設定が欠落・不正の場合は利用を一時拒否し、不明なサーバーを自動退出させることはありません。

通常は管理画面で管理してください。障害復旧に限り、サーバーへSSH接続した運営者は
`docker compose --env-file .env.linux -f docker-compose.linux.yml exec -T discord-bot python access_control.py list`
で設定を確認できます。同ツールの `block user ID`、`unblock user ID`、`block guild ID`、
`unblock guild ID` は緊急復旧用です。管理画面での変更と同時に実行しないでください。

6. 管理画面でサーバーNGを解除して再招待し、再利用できることを確認します。
